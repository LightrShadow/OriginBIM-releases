OriginBIM: repository audit and delivery roadmap

Reviewed 13 November 2026. Implementation release: 0.23.0. Estimates below are focused engineering effort for one developer, including regression work; they are not calendar delivery commitments or scheduled background work.

What happened to the assets

Version 0.22 applied a new-placement whitelist. Definitions were retained for compatibility, but only 33 physical entries and 113 explicit plan symbols were offered in the browser. This effectively removed the older catalogue from the user's workflow. Version 0.23 removes that browsing filter, restores all 877 existing definitions, and adds 130 converted parametric types: 1,007 catalogue entries total. Of these, 113 are explicit 2D symbols; 731 historical physical/reference entries remain unreviewed. Restored access is not a claim of geometric or manufacturer accuracy. Their cards say "Legacy · geometry not reviewed". The reviewed 33 entries remain available. Search covers every entry; pagination only limits simultaneous thumbnails.

The previous apartment migration removes only known generated sample section viewports, preserving the linked section definitions and user-authored viewports. It replaces identified sample visualization meshes with original planning solids. It does not erase arbitrary project assets. Version 0.23 does not delete library definitions or rewrite the user's drawing on load.

Current release: implemented and bounded

  • Direct section/elevation handles modify the shared model: move in the projected view, wall top, opening head/sill, solid/slab top/base, furniture height and placement. Invalid edits are rejected. A drag commits once; Escape cancels. Walls follow their level datum, so independent vertical wall translation is explicitly refused.
  • Click level text in a section/elevation to edit the floor name/elevation. Apply changes through the shared command history. Elements hosted on that level move with it. Select slabs/elements to edit their material in Properties; appearance overrides remain explicitly separate from model material.
  • Permanent 3D workspace icon. Push/pull supports straight-wall sides, ends and top, plus extrusion tops, undersides and outer profile edges. The opposite face stays fixed; connected endpoints and hosted stations are preserved. Curved/sloped/freeform/hole faces remain unsupported and return guidance.
  • Continuous whole-object plan dragging without grid stepping; screen-pixel magnetic vertex/edge capture with a larger release radius. Slab interior fills no longer intercept clicks; slab boundaries/vertices remain editable.
  • Native single/double swing, fixed/casement/sliding window and sliding-door presets. Window glazing and sash are distinct solids. Sliding leaves use separate tracks. Existing schematic rolling/folding/telescopic controls are retained for compatibility, and are not certified mechanisms.
  • Hosted doors/windows can be detached into local editable solid components, freely moved/rotated, then explicitly aligned and rehosted. Detaching heals the original wall cut. Host placement still prevents overlapping openings and invalid dimensions.
  • Bay-seat windows contain three physical glazing legs, frame members, a shaped solid seat and canopy; optional lintels have bearing/depth. The host wall retains material below sill and above head. A link to the actual generated stair step/landing sets sill elevation; changing stair rise updates it. Deleting the stair unlinks while retaining the last sill. With the link enabled, the selected host can grow to fit the head/lintel. This is a geometric assembly, not a structurally designed lintel.
  • 130 converted ConstructCraft parametric types, named editable parts, safe arithmetic formulas, original material names, IFC classes, source type properties and service connectors. Regenerating parameters creates an instance-local library definition and preserves other placements. Part deletion remains local and reversible. Project save/load, sections, neutral 3D export and IFC use those same parts.
  • Source links are removed from routine component properties/cards. Required attribution is kept under Library credits and in third-party notices.

ConstructCraft Components: conversion, not a proxy import

Pinned repository: https://github.com/francisreboucas/constructcraft-components/tree/0cd86f89eaa9d31e8b5a02f5690081e3902d973e

74 source families / 156 types. All 144 declared parameters are lengths. Sources contain 186 Box, 18 Cylinder, 36 Mesh, 7 Profile and 5 Revolution primitive records. The restricted evaluator supports named parameters, WallThickness, arithmetic and parentheses; it executes no imported code.

The adapter accepts boxes, cylinders and plan profiles, including rounded profile paths. It performs real box-void subtraction and concentric cylindrical void decomposition. Mixed/offset curved voids are rejected. Circular geometry is tessellated consistently. Plan-only swing graphics have no physical mass; in_plan visibility flags are honored.

52 families / 130 types convert. 26 types are deliberately rejected: 20 planting, 2 pendant lighting and 4 water-tank types require unsupported Mesh/Revolution geometry. No bounding boxes replace them. Geometry is generally simple source-authored planning massing; this is not a detailed manufacturer product library. Brazilian MEP fixture weights and standards remain source data, not universal sizing rules.

Converted door/window family entries currently place as free components and are labelled accordingly. They retain host-opening metadata, but do not yet cut a wall automatically. Use the native hosted opening tools for wall cuts. Full family-host adaptation must reconcile the source anchor, WallThickness, actual frame bounds, sill profile and operation metadata; merely substituting the outer bounding width would cut the wall incorrectly.

Assets are CC-BY-4.0 and credit ConstructCraft Components contributors. Attribution lives in notices. The native ConstructCraft application has a different GPL licence; it was studied as reference, not copied into OriginBIM.

Six further milestones after 0.23: approximately 18–33+ focused engineering weeks for one developer. The geometry and external-CAD adapter are the largest uncertainties. Parallel work may shorten elapsed time, but integration and regression gates remain necessary. No date is promised before the relevant acceptance gate passes.

What remains unfinished

Arbitrary sculpting/freeform surfaces, universal watertight Boolean editing, advanced section occlusion, full component constraint authoring, converted-family automatic hosting, every legacy asset's dimensional audit and external real-time CAD write-back are not finished in 0.23. Native desktop CAD/SketchUp application testing and full IFC schema validation are also not implied by TypeScript/model tests. There is no Windows installer in this update.

Validation for this release

131 Node regression tests passed, covering the original project workflows plus conversion formulas/voids, physical part edits, model serialization, section/IFC propagation, hosted opening detach/rehost, stair-step sill links, true-edge snapping and semantic face commands. Browser checks verified catalogue search (legacy dining layouts and converted table), instance parameter regeneration to 6 ft, section wall-height dragging and one-step undo, floor-label rename/apply/undo, and a 3D wall-side numeric push from 0.5 ft to 0.6 ft followed by Undo. These checks do not certify every restored legacy asset.
